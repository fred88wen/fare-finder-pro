## 這個里程碑做了什麼

M1 的通知器是免費的、誰訂閱都會收到信。M2 加上付費門檻：
**只有付過款（`active`）、或已取消但本期還沒到期（`cancelled` 寬限期內）的人，才會收到降價通知。**

付款狀態的唯一真相是**綠界打回來的 callback**（驗過 CheckMacValue），不是瀏覽器導回的頁面。

## 完成的元件

| 元件 | 角色 |
|---|---|
| `flight/ecpay`（Secrets Manager）| 商店代號/HashKey/HashIV/月費金額。改價＝改這裡一個數字，不用動程式 |
| `flight-save-subscription`（改）| 寫入 `pending_payment` + 產生簽好章的綠界定期定額表單（自動送出）；已付費者改走 JSON 就地更新目標價 |
| `flight-ecpay-return`（新）| 綠界 ReturnURL：**首期授權**的唯一真相，驗簽 → `active` + 設定本期到期日 |
| `flight-ecpay-period`（新）| 綠界 PeriodReturnURL：每月續扣結果，成功延長到期日；失敗只記次，連 6 次才 `expired` |
| `flight-ecpay-result`（新）| 綠界把瀏覽器用 **POST** 送回來，靜態網站會回 405；這支改成 302 導回 `/app` |
| `flight-cancel-subscription`（新）| 呼叫綠界 `Action=Cancel` 停止續扣，本地轉 `cancelled` 並**保留寬限期** |
| `flight-status-queue` + `flight-status-notification`（新）| 單一 SQS 消費者，依 `event_type` 分流歡迎信／取消信 |
| `flight-parser`（改）| **付費門檻在這裡生效**：只服務 `active` ∪ 寬限期內的 `cancelled`，並順手把過期的 `cancelled` 收成 `expired` |
| 前端 `/app`（改）| 依 `subscription_status` 顯示四種卡片狀態、取消訂閱按鈕、付款返回提示 |

新增 API 路由：`POST /ecpay-return`、`POST /ecpay-period`、`ANY /ecpay-result`、`POST /cancel`
（既有 `POST /subscribe`、`GET /subscriptions` 不變，API 仍為 `bmzjswvj8l.execute-api.us-east-1.amazonaws.com`）

## 訂閱生命週期

```
pending_payment ──(首期授權 ReturnURL)──▶ active ⇄（就地改目標價，不用重付）
      ▲                                     │
      │（重新訂閱並付款）                      │ /cancel（綠界 Action=Cancel，保留到期日）
      │                                     ▼
   expired ◀──(parser 發現到期日已過)── cancelled（寬限期內照常通知）
      ▲                                     ▲
      └────（連續 6 次續扣失敗）──────────────┘
```

## 已知限制（不是 bug）

- **寄信只送得到 fred88wen@gmail.com**：Resend 仍用沙盒寄件人 `onboarding@resend.dev`，寄給其他人會被擋（403）。要對外寄信必須在 M3 驗證自有網域。
- **`ExecTimes=999` 不是無限**：綠界定期定額是「扣款次數」不是「扣到取消為止」，999 個月≈83 年，實務上等同長期。
- **真正的續扣要等排程**：要看綠界排程真的打 `PeriodReturnURL`，得把 `PERIOD_TYPE` 環境變數暫時改成 `D`（每日）訂一筆、隔天再看 log。目前程式已支援用環境變數切換，不用改碼。
- **仍是測試商店**：真實收款要在 M3 申請正式商店代號、確認定期定額已開通，並把 `flight/ecpay` 的 `env` 改成 `prod`（程式會自動切換到 `payment.ecpay.com.tw`）。
